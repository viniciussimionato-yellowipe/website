# 11 · Definição de pronto

Um item do backlog só passa a "Feito" quando:

- [ ] o pull request foi revisto e aprovado por outra pessoa;
- [ ] a CI está verde (tipos, lint, formatação, testes unitários, conteúdo, E2E, Lighthouse);
- [ ] funciona em pt-PT e pt-BR (e em inglês, a partir do sprint 4);
- [ ] o conteúdo edita-se sem mexer em código (ficheiros de conteúdo hoje, CMS depois);
- [ ] o Lighthouse em mobile dá 90 ou mais em performance e 95 ou mais em acessibilidade e SEO;
- [ ] os eventos do item aparecem certos no modo de pré-visualização do GTM;
- [ ] não há dados pessoais no GA4 nem nos logs;
- [ ] o marketing validou em staging.

## O que é preciso para começar (fora do código)

**Decisões**

- [ ] CMS: Sanity ou Storyblok
- [ ] CRM e ATS atuais confirmados, com acesso à API
- [ ] Plataforma de consentimento
- [ ] Homepage v7 aprovada como base visual
- [ ] Publicar ou não faixas de preço
- [ ] Nome da prática de IA

**Acessos**

- [ ] DNS do domínio e site atual (lista de URLs e Search Console existente)
- [ ] Contas Google (GA4, GTM, Search Console) com a equipa de desenvolvimento como editora
- [ ] Repositório GitHub e conta de alojamento da Yellowipe

**Conteúdos**

- [ ] Textos pt-PT dos 3 modelos e dos 8 Top Services
- [ ] 6 casos com métricas e autorização escrita de cada cliente
- [ ] Logótipos de clientes com autorização
- [ ] Exportação do ATS para calcular os tempos até à shortlist e ao início

**Pessoas**

- [ ] Um responsável por responder aos leads em cada mercado, com o tempo de resposta acordado
